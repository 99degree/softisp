# MNN output tensor buffer ownership and AHardwareBuffer feasibility — evidence-backed study

- **Date:** 2026-11-26
- **Scope / method:** read-only study. No source file was modified, nothing was committed or pushed, no device run was performed. Claims are anchored to repository-relative paths and symbol names, without code-line citations.
  - MNN fork: `/data/data/com.termux/files/home/MNN` (HEAD `b2f05a51`), cited as `MNN/...`.
  - softisp: `/data/data/com.termux/files/home/softisp`, cited by repo-relative path. Citations to `anw/src/ahb_output.rs` and `docs/overview/ROADMAP.md` refer to the tree after the directed change that switched AHB output from opt-in to default-on; that change was not made by this study.
  - A grep over `MNN/include` for `AHardwareBuffer`, `hardware_buffer`, `getFd`, `exportMemory`, `getNativeHandle` returned **no matches**; the only public buffer-facing APIs are those cited in §4.
- **Question answered verbatim:** *What does MNN return as the output tensor buffer? Is it owned by MNN or does the caller need to free it? If so, can the caller make it as AHB?*

---

## 1. Direct answer / verdict

**Short answer:** `interpreter->getSessionOutput()` / `session->getOutput()` return a **borrowed raw `Tensor*` owned by the Session** (ultimately by the `Interpreter`). The caller must **not** `delete`/`free` that object. The buffer it points at (`Tensor::host<T>()` or `Tensor::deviceId()`) is **also owned by MNN/the backend** in the normal path — the caller never `free()`s it. You cannot "make" an arbitrary MNN output buffer into an AHB after the fact: there is no public API to allocate, wrap, export, or convert it. The supported route is the reverse: **the caller allocates its own AHB and gives it to MNN**, either as a host pointer for a copy (`copyToHostTensor`) or, in this fork's Vulkan backend, as a pre-bound device buffer (`setDevicePtr(..., MNN_MEMORY_AHARDWAREBUFFER)` before resize).

| Resource | Who owns it | Does the caller free it? | Evidence |
|---|---|---|---|

**Feasibility one-liners:** (A) use MNN's buffer as AHB — **no**. (B) caller AHB + `copyToHostTensor` — **yes, with a copy**. (C) caller AHB bound before resize — **yes, zero-copy in this fork**, with strict ordering and unvalidated fences/coherency. (D) OpenCL Express `copyToDevicePtr` — **unreachable in softisp**.

## 2. Evidence: session / output tensor object lifetime

1. **Creation and ownership.** `createSession()` delegates to `createMultiPathSession()`, which wraps the new `Session` in `std::unique_ptr` and stores it in `Content::sessions`. `Content` holds `std::vector<std::unique_ptr<Session>> sessions` and a `std::map<Tensor*, const Session*> tensorMap`. The public header says a created session "will be managed in net" (`MNN/source/core/Interpreter.cpp`, `MNN/include/MNN/Interpreter.hpp`).
2. **Getter returns a borrowed pointer.** `Interpreter::getSessionOutput()` calls `session->getOutput(name)`, inserts `(tensor, session)` into `tensorMap` (only for later `resizeTensor` association), and returns the raw pointer — it allocates nothing. `Session::getOutput()` returns `mInfo.outputTensor[...]` from its own map; `getOutputAll()` returns a `const&` to that map. The tensors in `mInfo.allTensors` are `std::shared_ptr<Tensor>` created with `new Tensor` (`MNN/source/core/Interpreter.cpp`, `MNN/source/core/Session.cpp`).
3. **Across `runSession()` / `run()`.** `Interpreter::runSession()` only calls `session->run()`. `Session::run()` executes pipelines and returns. Neither creates nor deletes `Tensor` objects, so the pointer stays valid across frames. `resizeSession()` / `Session::resize()` re-acquires **memory** but not the tensor objects. The header's instruction is that output tensor buffers (host or deviceId) should be retrieved *after* resize (`MNN/source/core/Interpreter.cpp`, `MNN/source/core/Session.cpp`, `MNN/include/MNN/Interpreter.hpp`).
4. **Destruction.** `Session::~Session()` clears `mInfo.allTensors`, `mPipelines`, and runtimes → all `Tensor` destructors run. `Interpreter::~Interpreter()` clears `Content::sessions` (deleting every `Session`) and `tensorMap`, then deletes `Content`. `releaseSession()` erases the session from `Content::sessions` and the matching `tensorMap` entries. After either, any previously returned `Tensor*` dangles (`MNN/source/core/Session.cpp`, `MNN/source/core/Interpreter.cpp`).
5. **`Session_Output_User` is not ownership transfer.** The enum comments distinguish "output tensor depends on session" vs "can be separated from session", but in code the flag is only passed as `outputStatic` into `Pipeline` and makes output tensors use `Backend::STATIC` storage. There is no public API that transfers the `Tensor*` to the caller. Caller must still not delete it (`MNN/include/MNN/Interpreter.hpp`, `MNN/source/core/Session.cpp`, `MNN/source/core/Pipeline.cpp`).

## 3. Evidence: host buffer ownership and `copyToHostTensor`

1. **What "the output buffer" means on the host.** The header states plainly: host tensor data lives in `host` and "its memory is allocated malloc directly"; device tensor data lives in `deviceId` and "its memory is allocated by session's backend". `host<T>()` is just a cast of `mBuffer.host`; `deviceId()` is `mBuffer.device`; `buffer()` exposes the raw `halide_buffer_t`. The constructor initializes `device = 0`, `host = nullptr`, `flags = 0` (`MNN/include/MNN/Tensor.hpp`, `MNN/source/core/Tensor.cpp`).
2. **MNN-allocated host memory (caller does not free it, only the tensor).** `Tensor(const Tensor*, ..., allocMemory=true)` sets `memoryType = MEMORY_HOST` and `mBuffer.host = MNNMemoryAllocAlign(size(), MNN_MEMORY_ALIGN_DEFAULT)`; alignment constant is 64 in `MNN/source/core/MNNMemoryUtils.h`. `~Tensor()` frees that pointer **only** when `memoryType == MEMORY_HOST`. `Tensor::create(..., userData=nullptr, ...)` takes this path and `createHostTensorFromDevice()` uses it for the returned host tensor (`MNN/source/core/Tensor.cpp`, `MNN/source/core/MNNMemoryUtils.h`).
3. **External host pointer (caller owns it).** With `userData != nullptr`, `Tensor::create()` sets `ownData = false`, constructs the tensor with `allocMemory=false`, and assigns `result->buffer().host = (uint8_t*)userData`. `memoryType` therefore stays at its default `MEMORY_BACKEND`, and the destructor's `MEMORY_HOST` guard does not free it. MNN never `free()`s the caller's pointer (`MNN/source/core/Tensor.cpp`, `MNN/source/core/TensorUtils.hpp`).
4. **`copyToHostTensor` writes into caller memory; it does not allocate.** `Tensor::copyToHostTensor()` merely checks the source backend and calls `bn->onCopyBuffer(this, hostTensor)`. On CPU, `CPUTensorConverter::convert()` does `::memcpy(ob.host, ib.host, ...)`. On Vulkan, the GPU→host branch calls `_requireHostBuffer()`, copies device→staging with `vkCmdCopyBuffer`, then `_copyBufferToTensor()`, which does `::memcpy(dest->host<float>(), sourcePtr, dest->usize())`. **If the destination `Tensor` has a null host pointer, MNN does not allocate one — the copy has no valid destination.** Safe use requires the caller to supply a tensor with a valid host buffer: either a MNN-allocated one (`Tensor::create(..., nullptr, ...)`, freed with the tensor) or an external pointer that the caller keeps alive (e.g. an AHB mapping). The mirror direction, `copyFromHostTensor()`, similarly delegates to `bn->onCopyBuffer(hostTensor, this)` (`MNN/source/core/Tensor.cpp`, `MNN/source/backend/cpu/CPUTensorConvert.cpp`, `MNN/source/backend/vulkan/buffer/backend/VulkanBackend.cpp`).
5. **`map`/`unmap` are another path and do allocate.** `Tensor::map()` with no backend override `malloc`s `size()` bytes and fills it via `onCopyBuffer`; `unmap()` frees that pointer. This is a **copy**, not an AHB mapping, and must be paired with `unmap()`. Vulkan does not override these hooks, so `map()` on a Vulkan output copies (`MNN/source/core/Tensor.cpp`).
6. **Session-owned CPU host buffers are backend memory, not tensor-allocated.** `CPUBackend::allocBuffer()` sets `buffer.host = chunk.ptr()` from a `BufferAllocator`; `CPUMemObj::~CPUMemObj()` returns the chunk to the allocator. `Backend::onAcquireBuffer()` stores the `MemObj` in `describe->mem`; `onReleaseBuffer()` clears it. `_needRelease()` deliberately skips tensors whose `memoryType` is `MEMORY_HOST`/`MEMORY_OUTSIDE` (`MNN/source/backend/cpu/CPUBackend.cpp`, `MNN/source/backend/cpu/CPUBackend.hpp`, `MNN/source/core/Backend.cpp`, `MNN/source/core/Pipeline.cpp`).

**Conclusion for option B:** writing an AHB CPU mapping through a temporary `Tensor::create(shape, type, map_ptr, ...)` + `copyToHostTensor()` + `delete` is safe provided the mapping stays locked and the `Tensor` shape/type match. MNN writes into caller memory and does not free it.

## 4. Evidence: device buffer / backend ownership and public API limits

1. **Public surface is read/bind-only.** `Tensor::getDeviceInfo(void* dst, int forwardType)` requires `backend()->type() == forwardType`, otherwise returns false; it delegates to `Backend::onGetTensorInfo`. `Tensor::setDevicePtr(const void*, int)` merely stores `mBuffer.flags = memoryType; mBuffer.device = (uint64_t)devicePtr` and returns `true` — **no allocation, no import, no ownership change**. `MNN_MEMORY_AHARDWAREBUFFER = 14` is a memory-type flag, not a backend, so `getDeviceInfo(dst, MNN_MEMORY_AHARDWAREBUFFER)` returns false (`MNN/include/MNN/Tensor.hpp`, `MNN/include/MNN/MNNForwardType.h`, `MNN/source/core/Tensor.cpp`).
2. **What `getDeviceInfo` actually returns.** Vulkan's `onGetTensorInfo()` writes only `buffer`, `offset`, `size` into `MNNVulkanTensorContent`; that struct is `{VkBuffer buffer; VkDeviceSize size, offset; halide_type_t realType; int32_t mask;}`. It is a raw handle snapshot — **no AHardwareBuffer, no fd, no transfer of ownership**. There is no equivalent OpenCL/Metal-export API for AHB; grep over `MNN/include` found no AHB symbol (`MNN/source/backend/vulkan/buffer/backend/VulkanBackend.cpp`, `MNN/include/MNN/MNNSharedContext.h`).
3. **Backend memory is created and freed by the backend.** `Backend::StorageType` and `Backend::MemObj` are defined in `MNN/source/core/Backend.hpp`. `onAcquire` returns a `MemObj` that the backend stores on the tensor. Vulkan's normal branches allocate from a buffer pool, set `tensor->buffer().device` to a `VulkanBuffer*`, and return `VulkanMemRelease`, whose destructor frees the `MemChunk`. The caller must not free these (`MNN/source/core/Backend.hpp`, `MNN/source/core/Backend.cpp`, `MNN/source/backend/vulkan/buffer/backend/VulkanBackend.cpp`).
4. **The fork's AHB import is per-tensor and lazy.** `VulkanAhbMemObj` (holding `shared_ptr<VulkanBufferFromAHB>`) and `getAhbMem()` are file-local to `MNN/source/backend/vulkan/buffer/backend/VulkanBackend.cpp`; `TensorUtils::setSharedMem/getSharedMem` are declared in `source/core`, not `include/MNN`. `VulkanBackend::onAcquire()` checks `flags == MNN_MEMORY_AHARDWAREBUFFER` **first**: it requires a non-zero device pointer, imports via `VulkanBufferFromAHB::create()` when the AHB id differs or size grew, sets `des->offset = 0`, and stores the `MemObj` on the tensor. Otherwise the normal pool path runs. `getBuffer()` resolves the imported `VkBuffer`. Therefore an AHB bound **after** resize is ignored: the tensor already has pool memory and no `VulkanAhbMemObj` (`MNN/source/backend/vulkan/buffer/backend/VulkanBackend.cpp`, `MNN/source/core/TensorUtils.hpp`, `MNN/source/core/TensorUtils.cpp`).
5. **The real Vulkan import and its ownership.** `VulkanBufferFromAHB::create()` requires `VK_KHR_external_memory`, `VK_ANDROID_external_memory_android_hardware_buffer`, `VK_KHR_dedicated_allocation`, `VK_KHR_get_memory_requirements2`, `VK_KHR_bind_memory2`; it returns `nullptr` if `vkGetAndroidHardwareBufferPropertiesANDROID` is unavailable. It creates a `VkBuffer` with `VK_EXTERNAL_MEMORY_HANDLE_TYPE_ANDROID_HARDWARE_BUFFER_BIT_ANDROID`, queries AHB properties/allocationSize, passes `VkImportAndroidHardwareBufferInfoANDROID` inside a dedicated allocation, and calls `vkAllocateMemory` / `vkBindBufferMemory`. **There is no `AHardwareBuffer_acquire`/`AHardwareBuffer_release` in this path.** Destruction frees only MNN's `VkBuffer`/`VkDeviceMemory`. The caller owns the AHB reference (`MNN/source/backend/vulkan/component/VulkanBuffer.cpp`).
6. **Synchronization is an internal fence, not an AHB fence.** `Tensor::wait()` → `onSync()` calls `_finish()`. There is no imported/exported AHB fence, no cache invalidation, and no producer/consumer fence handoff in the import path. Also, the required extensions are only **probed/logged** in `MNN/source/backend/vulkan/component/VulkanDevice.cpp`; the device creation list does not add them, so driver-dependent enablement is unverified (`MNN/source/core/Tensor.cpp`, `MNN/source/backend/vulkan/buffer/backend/VulkanBackend.cpp`, `MNN/source/backend/vulkan/component/VulkanBuffer.cpp`, `MNN/source/backend/vulkan/component/VulkanDevice.cpp`).

## 6. softisp recommendation and required call order

**Recommendation:** keep two paths and retain B (host copy) as the safety fallback. Per user direction, C is **default-on** (`anw/src/ahb_output.rs`), with explicit opt-out switches and an API-26 fail-closed guard. C requires a caller-owned, stable, generously sized AHB and the exact call order below. Never try A; never delete MNN-returned tensors or free their buffers.

Required call order for the landed zero-copy output path:

1. **Caller owns the AHB.** `AhbOutputSlot::new()` allocates `AHARDWAREBUFFER_FORMAT_BLOB` with `CPU_READ_OFTEN | GPU_DATA_BUFFER`, capacity `16 × w × h × 4` rounded to a power of two, locks it once and keeps the mapping stable (`anw/src/ahb_output.rs`). One slot per worker; no swapping.
2. **Publish both views into `ProcessParams`.** `slot.buffers()` yields `AhbBinding` (for `setDevicePtr`) and `(map, capacity)` (for `copyToHostTensor` fallback); `anw/src/pipeline_runner.rs` prepares and sets them per frame (`wait_free()` → `mark_busy()`).
3. **Bind before resize.** `MnnEngine::prepare()` sets `zero_copy`/`output_ahb` and, on a geometry change, calls `mnn_import_ahb_as_device_memory` **before** `slot.sess.resize()` (`cam-rust/cam-isp/src/mnnengine.rs`). FFI `mnn_import_ahb_as_device_memory` obtains an fd only diagnostically and closes it, then calls `tensor->setDevicePtr(ahb, MNN_MEMORY_AHARDWAREBUFFER)` (`cam-rust/cam-isp/mnn_sys/mnn_wrapper.cpp`). The actual Vulkan import happens later in `onAcquire` (`MNN/source/backend/vulkan/buffer/backend/VulkanBackend.cpp`).
4. **Validate at run time.** `run_prepared()` checks geometry, AHB generations, output pointer identity and capacity (`cam-rust/cam-isp/src/mnnengine.rs`). Warn about unwaitable input AHB fences.
5. **Run.** With AHB active, call `mnn_run_ahb_output()` (`cam-rust/cam-isp/src/mnnengine.rs`): it verifies that the caller's pointer is a real AHardwareBuffer with enough
bytes for the tensor, refuses an input shape change that would force a resize,
restores a lost binding only when MNN cleared the flags but left the caller's
AHB pointer in place, uploads the input via `copyFromHostTensor`, calls
`runSession`, checks element count vs capacity, and calls
`output->wait(MAP_TENSOR_READ, true)` (`cam-rust/cam-isp/mnn_sys/mnn_wrapper.cpp`).
**No `copyToHostTensor`.**
6. **Fallback.** A `-10` (binding lost) re-runs via `mnn_run_true_zero_copy()` into the *same AHB mapping* (`cam-rust/cam-isp/src/mnnengine.rs`); non-AHB callers use the same host-copy path. That path creates an external-pointer host tensor and ends in `copyToHostTensor` (`cam-rust/cam-isp/mnn_sys/mnn_wrapper.cpp`).
7. **Handoff.** `IspFrame::new_external()` avoids a second allocation (`cam-rust/cam-isp/src/pipeline/types.rs`); `frame.external_data = ExternalBuffer { ptr, len }` (`cam-rust/cam-isp/src/mnnengine.rs`). Presenter gets an `AhbView` (`anw/src/pipeline_runner.rs`, `anw/src/ahb_output.rs`) and marks the slot free after the blit.
8. **Do not rely on `mnn_release_ahb_device_memory` for cleanup.** It only calls `setDevicePtr(nullptr, 0)` (`cam-rust/cam-isp/mnn_sys/mnn_wrapper.cpp`); it does not destroy the imported `VkBuffer`/`VkDeviceMemory` (those die with the tensor describe / backend). The intended lifetime is one binding per worker session.

Related studies to consult (not modified): `docs/mnn/20261126-mnn-vulkan-ahb-handling-study.md` (call chain, sizing, fences), `docs/mnn/20261126-mnn-opencl-ahb-output-study.md` (why OpenCL is not an alternative), `docs/isp/20261126-output-copy-zero-copy-audit.md` (root cause of the `to_vec()` copy), `docs/isp/20261126-ahb-repo-wide-analysis.md` (why `anw/src/ahb_output.rs` is the only producer-side owner).

## 7. Lifetime rules — "who frees what"

| Action | Correct owner / cleanup |
|---|---|
| `Tensor* t = interpreter->getSessionOutput(...)` | Borrowed. Never `delete t`, never `free(t->host<float>())`, never `free((void*)t->deviceId())`. Valid until `releaseSession(session)` or `Interpreter::destroy/delete` (`MNN/source/core/Session.cpp`, `MNN/source/core/Interpreter.cpp`). |
| `Tensor::create(shape, type, nullptr, ...)` (`ownData=true`) | MNN allocates aligned host memory; caller `delete`s / `Tensor::destroy`s the tensor, destructor frees the host buffer (`MNN/source/core/Tensor.cpp`). |
| `Tensor::create(shape, type, external_ptr, ...)` (`ownData=false`) | Caller owns `external_ptr`; delete the tensor object only, keep the pointer alive/locked until all copies are done (`MNN/source/core/Tensor.cpp`). Used by softisp for input and output host tensors (`cam-rust/cam-isp/mnn_sys/mnn_wrapper.cpp`). |
| `createHostTensorFromDevice()` | Returns a new MNN-owned host tensor; caller deletes it; the copy is device→host (`MNN/source/core/Tensor.cpp`). |
| `output->copyToHostTensor(dst)` | Writes into `dst->host`; does not allocate; caller supplies valid host memory (`MNN/source/core/Tensor.cpp`, `MNN/source/backend/cpu/CPUTensorConvert.cpp`, `MNN/source/backend/vulkan/buffer/backend/VulkanBackend.cpp`). |
| `output->map(...)` / `unmap(...)` | MNN `malloc`s for read and frees in `unmap`; always pair them; this is a copy (`MNN/source/core/Tensor.cpp`). |
| Vulkan device buffer / imported AHB | Backend owns `VkBuffer`/`VkDeviceMemory`; `VulkanMemRelease`/`VulkanBufferFromAHB` destructors free them (`MNN/source/backend/vulkan/buffer/backend/VulkanBackend.cpp`, `MNN/source/backend/vulkan/component/VulkanBuffer.cpp`). Caller never frees them. Caller **does** own/release the `AHardwareBuffer` it created (`anw/src/ahb_output.rs`), and must keep it alive while imported. |
| `mnn_release_ahb_device_memory()` | Only clears `flags`/`device` (`cam-rust/cam-isp/mnn_sys/mnn_wrapper.cpp`); not a resource release. |
| `releaseSession` / interpreter destroy | Destroys tensors and backend memory; all previously returned output pointers become invalid (`MNN/source/core/Session.cpp`, `MNN/source/core/Interpreter.cpp`). |

## 8. Risks / open questions / on-device validation

1. **Extension enablement.** The AHB extensions are only logged as "available" (`MNN/source/backend/vulkan/component/VulkanDevice.cpp`) and are not pushed into `deviceExtensions`. If the driver requires explicit enablement, `vkAllocateMemory` with the import struct (`MNN/source/backend/vulkan/component/VulkanBuffer.cpp`) can fail; `onAcquire` then returns `nullptr` (`MNN/source/backend/vulkan/buffer/backend/VulkanBackend.cpp`). Validate `[AHB-PROBE]` and `[ZERO-COPY] AHB imported ok` traces on device.
2. **Capacity.** `VulkanBufferFromAHB::create()` sets `bufInfo.size = alignSize` and allocates `ahbProps.allocationSize` without checking `allocationSize >= alignSize` (`MNN/source/backend/vulkan/component/VulkanBuffer.cpp`). softisp now allocates a 16× power-of-two slot and validates it against the prepared worst case before binding (`anw/src/ahb_output.rs`, `cam-rust/cam-isp/src/mnnengine.rs`), so a 4-channel fused output no longer fits only by accident. An in-run resize is rejected and sent to the host-copy fallback rather than rebinding over MNN's newly acquired device buffer.
3. **Fences / coherency.** `wait()` is only an internal `VkFence` flush (`MNN/source/backend/vulkan/buffer/backend/VulkanBackend.cpp`); no AHB acquire/release fd is imported or exported, and the CPU mapping stays live across GPU writes (`anw/src/ahb_output.rs`). The busy flag is a CPU protocol (`anw/src/ahb_output.rs`, `anw/src/pipeline_runner.rs`). Input AHB acquire fences are explicitly not waited (`cam-rust/cam-isp/src/mnnengine.rs`). Stale reads/tearing remain possible until validated.
4. **Binding timing / stale state.** Binding after resize is ignored; swapping AHBs without a new `onAcquire` keeps the old `VkBuffer` (`MNN/source/backend/vulkan/buffer/backend/VulkanBackend.cpp`). The AHB branch does not set `tensor->deviceId()`, so clearing with `setDevicePtr(nullptr, 0)` leaves a stale/zero device id (`MNN/source/backend/vulkan/buffer/backend/VulkanBackend.cpp`).
5. **API baseline.** AHB needs API 26 while the APK declares 24; the default-on path fails closed below 26 (`anw/src/ahb_output.rs`).
6. **Not end-to-end zero-copy.** Camera capture still copies into `Vec` and presentation still blits through `ANativeWindow_lock` (`docs/isp/20261126-ahb-repo-wide-analysis.md`). The AHB is a BLOB GPU data buffer, not a queued compositor image.
7. **Documentation contradictions to keep flagging.** `docs/isp/20261126-output-copy-zero-copy-audit.md` overstates `Tensor::wait` as a CPU-visibility guarantee; it is only an internal Vulkan fence wait. The wrapper header and the C++ implementation now state that the fd is diagnostic-only and the real import happens in the MNN fork's `onAcquire`. `docs/mnn/20261126-mnn-vulkan-ahb-handling-study.md` and `docs/isp/20261126-ahb-repo-wide-analysis.md` list further historical stale docs.

Check for no `AHB output import ... failed` / `-10`, no black frames or tearing at 1600×1200 / 1920×1080 / 3840×2160, no Vulkan validation errors, correct slot recreation on geometry change (`anw/src/pipeline_runner.rs`), and API-26 guard on an older device. Until that passes, keep the host-copy fallback.
